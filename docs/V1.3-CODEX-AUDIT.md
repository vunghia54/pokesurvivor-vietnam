## Kiến trúc đã kiểm tra

Game JavaScript/canvas, không đổi framework. `dev.html` nạp nguồn; `tools/build.js` tạo `index.html`, `js/app.min.js` có minify/obfuscation và `version.json`. Từ điển nguồn nằm trong `js/data/lang-*.js`, bản phân phối trong `js/lang/`.

`js/core/db.js` quản lý đăng ký/đăng nhập, bộ nhớ local và Cloud Save. Firestore lưu `saves`, `names`, `profiles`, `friendships`, `inv`, `lb`. RTDB quản lý presence, thành viên phòng và signaling. `js/net/net.js` kết nối WebRTC theo mô hình host–guest; `js/net/coop.js` giữ host phụ trách trạng thái thế giới. Không sửa thuật toán chiến đấu, AI, boss, chỉ số hay tỷ lệ gacha.

Có thể cấp access token qua biến môi trường `FIREBASE_AUDIT_ACCESS_TOKEN` trong terminal; không đưa token vào repository hay báo cáo.

Bản `firestore.rules` tại HEAD trước sửa giống các snapshot local `backup/rules_v1.2/firestore.rules` và `backup/rules_v1.3/firestore.rules`. Snapshot `backup/production_pre_v1.2` khác. Điều này chỉ chứng minh sự nhất quán của các file local, không chứng minh production đã cập nhật.

Firestore không đổi schema save, names, profiles, friendships, invitations và điểm solo cũ. Thay đổi chỉ siết mode/UID nhóm. Đã thêm test tạo yêu cầu kết bạn → chỉ người nhận chấp nhận → gửi lời mời, cùng bài kiểm tra group score legacy. Các bài này đang bị chặn bởi Emulator.

**Giao thức Co-op mới không tương thích với phòng/client cũ** thiếu `slots`, hoặc queue không có tiền tố UID. Không deploy riêng Rules này khi client v1.2/v1.3 cũ vẫn tạo phòng. Cần phối hợp bảo trì Co-op, chờ các trận cũ kết thúc, cập nhật client và Rules sau phê duyệt, yêu cầu tải lại phiên bản mới. Không chuyển đổi/xóa save để đổi giao thức phòng.

Firestore Rules không thể tự kiểm chứng ai thực sự tham dự trận trong RTDB. Một người biết UID người khác vẫn có thể khai thành tích nhóm gồm các UID khác nhau. Bản vá chống UID trùng không phải chống gian lận hoàn chỉnh; cần thiết kế chứng thực trận/đồng thuận thành viên nếu đây là điều kiện phát hành.

## Chạy local và các bước còn thiếu để phát hành

Từ PowerShell trong `D:\pokesurvivor-main`:

```powershell
npm test
npm start
```

Mở `http://127.0.0.1:8766/dev.html` để debug hoặc `/index.html` để xem build. Cấu hình localhost dùng Firebase Emulator, không dùng production. Để dùng đăng nhập/Co-op local cần chạy Auth 9099, Firestore 8080, Database 9000. Nếu cổng đã có server, kiểm tra tiến trình đang chạy; không tự tắt dịch vụ không rõ chủ sở hữu.

Với Firebase CLI đã cài và môi trường cho phép cổng localhost:

```powershell
# Terminal A: giữ emulator chạy cho browser smoke
firebase emulators:start --only auth,firestore,database --project plucky-courier-365002
# Terminal B: static server
npm start
# Terminal C: kiểm thử mọi suite và 2/3/4 browser
npm run test:all
npm run test:coop
```

Hoặc đặt `FIREBASE_CLI_PATH` tới file `firebase-tools/lib/bin/firebase.js` đã cài rồi chạy `npm run test:emulators` để tự bật/tắt emulator khi chạy toàn bộ suite Rules. Không chạy hai bộ emulator cùng lúc trên cùng cổng. Không dùng `--import`/`--export-on-exit` với dữ liệu production.

Các điều kiện phát hành còn thiếu:

1. Chạy thành công tất cả bài trên Firebase Rules engine thật, gồm test người thứ 5 và hai claim đồng thời. Xem kỹ lỗi compiler Rules nếu xuất hiện; hiện chưa được xác minh compiler.
2. Đăng nhập Firebase CLI đúng tài khoản/project và chạy audit production chỉ đọc; so sánh snapshot, xác nhận Firestore friends/group/save với production hiện hành.
3. Chạy smoke 2/3/4 browser, rồi chơi thật trên PC và điện thoại: cùng mạng và khác mạng, 8 kỹ năng, rớt mạng host/guest, kick, chết/hồi sinh, kết thúc, login/logout, save tải lại và group leaderboard. Chưa có TURN thuộc bản Việt Nam; mạng NAT chặt có thể không kết nối trực tiếp được.
4. Chốt cách dọn phòng đóng bị bỏ lại và mức độ chống giả thành tích nhóm; xác định đây có phải release blocker không.
5. Kiểm tra remote/Pages workflow bằng quyền đọc; tạo commit/PR để review bản diff này. Tag `v1.3-vi` hiện chưa chứa các sửa đổi Codex, không tự ghi đè tag đó.
6. Sau khi có bằng chứng các bước trên đạt và người dùng xác nhận triển khai: backup Rules production, phối hợp chuyển giao thức phòng/client, chạy build bảo vệ mã + export + SEO, cập nhật nhánh/nguồn GitHub Pages theo cấu hình đã xác minh, kiểm tra phiên bản public và theo dõi lỗi.
